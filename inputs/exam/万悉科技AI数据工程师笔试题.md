# 万悉科技｜数据 + AI 工程师笔试题

Candidate Technical Assessment 

笔试说明 共 2 道题，分别考察数据工程与 AI/RAG 工程能力。建议 3 天内完成。不要求完整生产级系统，但需体现清晰的设计、可运行或接近可运行的核心代码，以及对性能、数据质量和工程落地的理解。

## 一、数据工程：销售数据查询与 API 设计

背景：Trendee 平台持续从多个数据源采集商品销售数据，需要向前端提供某类商品的销量趋势查询，并支持任意日期范围、多平台筛选和高并发访问。

附件数据

请使用附件《样例销售数据.xlsx》。共 300 条记录，覆盖 2024 年 1–3 月及多个平台，并保留部分标题差异、重复记录和时间边界情况。

## 任务

• 返回 “maxi dress” 相关商品的日销量趋势，支持 start_date、end_date 以及一个或多个平台。

• 自行定义并说明 “maxi dress” 的识别/归一化规则。原始 category 仅为 dress 等粗粒度类别，不能直接等同于 maxi dress。

自行选择数据库/存储方案并设计 schema / mapping / 索引结构；可继续使用 Elasticsearch，也可选择PostgreSQL、ClickHouse 等。

• 提供核心 SQL 或 Elasticsearch Query，结果至少支持按日期、平台分组统计销量。

• 设计 RESTful API，给出路径、参数、典型返回结构和必要的错误处理。

• 说明大数据量与高并发下的优化方案及关键取舍，例如索引、预聚合、缓存、分区/分片、冷热数据等。

• 说明重复数据、标题归一化、timestamp / 时区及异常记录的处理方式。

## 需要提交

• 系统/数据设计说明（可附架构图）、schema / mapping、核心查询、API 示例、性能与数据质量说明、README。

## 二、AI 工程：基于 RAG 的品牌内容写作系统

背景：我们会提供一份万悉科技品宣 PDF。请基于该 PDF 设计一个简单的 RAG 写作系统，用于生成官网 Blog、FAQ、品牌介绍或产品介绍。

目标流程：读取 PDF → 解析与切分 → 建立检索索引 → 输入主题 → 检索资料 → 构建上下文 → 生成内容 → 展示引用依据。

## 示例输入

请基于万悉科技品宣 PDF，生成一篇官网 Blog，主题是：为什么中国出海品牌需要进行 GEO 优化？

## 任务

• 实现 PDF 解析、Chunk 切分、索引/向量化、检索、上下文构建和内容生成的完整链路。

• 输出结构完整的文章，包括标题、导语、小标题和结尾；FAQ 可选。

• 展示所依据的 PDF 资料片段或页码，能够进行基本引用溯源。

• 不得编造 PDF 中没有的公司事实、客户案例、数据或技术指标。

• 说明 Chunk、检索、Prompt、上下文组织和幻觉控制策略；资料不足时应明确处理，而非直接猜测。

• 提交核心代码。可使用 Streamlit / Gradio / FastAPI / Notebook / CLI；可运行 Demo 为加分项。

## 需要提交

• RAG 设计、PDF/Chunk 策略、检索与上下文构建、完整 Prompt、幻觉控制与引用溯源、核心代码、示例输出、README。

## 三、统一提交要求

• 建议完成时间：3 天；代码需直接提交并尽量可运行，不接受仅文字方案。

• 技术栈不限，可使用主流数据库、向量库、框架和大模型 API。

• 允许使用 AI 编程工具，但面试时需能够解释架构、核心代码、Prompt、数据处理逻辑和关键技术取舍。

• 代码、README、方案说明及 Demo（如有）请提交至 career@trendeetech.cn。

## 四、我们重点关注

• 数据工程：数据模型、查询/API、数据质量、大数据量和高并发。

• AI/RAG：检索、上下文构建、引用溯源、幻觉控制，而非只调用一次模型 API。

• 工程落地：代码结构、可运行性、异常处理、可维护性和 README。

• 技术判断：能够解释数据库、索引、缓存、RAG 方案或模型选择背后的理由。
